# 23. 実装受け入れ・検証手順（v0.5）

**この章は実行すべきQA計画であり、テストが合格したという記録ではない。** まずゲームコアの単体テストを通し、次にブラウザ操作とアセット品質を確認する。

## Tier 1: 仕様データの静的検証
- configがschema `spec/mvp_config.schema.json` に合致する。
- saveのmain/backup候補が `spec/mvp_save.schema.json` に合致し、単なる型検査でなくフェーズ/注文/収支の相互不変条件も追加で検証する。
- configの各食材原価合計は430円、初期在庫10食分、通常価格980円、P1〜P6の得点合計100点、客重み合計100。
- `spec/mvp_test_vectors.json` の全ケースを実装ロジックのテスト入力として扱い、記載済みの利益/在庫/評判/ランクを照合する。
- 変更された数値にテストベクトルの更新が伴わなければレビュー拒否。

## Tier 3: UI E2E
1. タイトル→新規→MORNING仕入/たれ編集→OPEN→P1..P6→REACTION→RESULT→UPGRADE→翌日。
2. COOK/P3中にEsc→タブ非表示→復帰→再開で工程タイマーが飛ばない。
3. P2ドラッグ中にウィンドウ外へ出る→中断後に確定済みセルが残り未確定ストロークは加点されない。
4. 3件のqueuedカードで最古以外を選んで調理しても待機・経済・客の順序が破綻しない。
5. 仕入不可・セーブ不可・設備未解放・空の注文列・セーブなし等のerror/disabled/empty状態が正しく表示される。
6. SSS/S/A/B/C/Fを強制デバッグ入力で表示し、店主と顧客の顔/料理/得点/台詞が重ならない。
7. キーボードのみでタイトル・朝・仕入れ・工程P1〜P6・設備購入を完走できる。
8. UIのスクリーンショットを1280×720/1600×900/1920×1080/1366×768で記録、文字/ボタン/注文表示が見切れない。
9. 保存中に終了を連打、同一注文の提供を連打しても不変条件が保持される。
10. IndexedDB/mainが壊れた時にbackup復元を選択でき、ユーザーに復旧結果が説明される。

## Tier 4: 画像/音/体験
- 主人公は指定の銀〜薄紫双お団子、ピンク瞳/ヘアピン。参照画像のデニム服を複製しない。
- 顧客4種×ランク6差分、完成かつめしcanonical、料理工程6、UI枠・背景が分離されている。
- 画像のライセンス、sourceWorkflow、チェック状態をmanifestへ記録、approved以外を配布しない。
- 効果音OFFでも進行がわかる。SSS/S/A/B/C/Fは表情と文字のみでも評価を識別できる。
- 調理を最低5人でプレイテストし、迷った工程・時間・疲労感・リトライ回数を記録。7日シミュレーションは100 seed以上。
- 重要画面の対比画像をissueに添え、合成破綻や人物の役割混同を防ぐ。

## リリースブロッカーと受け入れ
**ブロッカー**: セーブ破損/消失、売上・原価の二重計上、無限queue、入力で進行不能、残客がいて即閉店、別人物の評価代行、画面操作不能、著作権未確認素材の配布。

**MVPが完了したと言える条件**: S01〜S24合格、E2E10項目合格、Day1の8注文完走、Day7節目・翌日継続、重要UI全画面レイアウト検査、アセット採用判定、ブロッカー0。

## 状態の記録
- Issueには仕様ID・コミット・テスト結果・失敗seed・画像/ログ・再発防止策を残す。
- ローカル検証コマンドを用意（実装後）: `npm run typecheck`、`npm run test`、`npm run test:e2e`、`npm run build`。
- GitHub Actionsは前提とせず、ローカル検証ログをPRに添付する。
- これらは**これから実装し実行するテスト**である。今回の仕様レビューでは実際の結果を測定していない。

## 長期データ/自動保存テスト（追加）
- S21: Day1終了→UPGRADEで設備購入→NEXT_DAY。Day1の `dailyLedger` が一度だけ `careerLedger` に加算され、当日のorders/appliedCommandIdsは空になる。旧Day1コマンドをDay2で再送したらtargetDay不一致で拒否。
- S22: Day7 RESULTの累計売上 = 過去6日careerLedger.salesYen+Day7 dailyLedger.salesYen。画面再表示でも累計が増えない。
- S23: 調理タイマー中に2秒間隔の自動保存→強制終了→最後にcommit済みのsnapshotから復帰。未保存2秒以下は失われ得るが、二重会計や経過時間の飛びは無い。
- S24: autosave失敗→未保存警告→SAVE_QUIT失敗ならTITLEへ遷移しない。復旧して保存成功したら終了可。
- リリース条件にはS01〜S24を含める。
