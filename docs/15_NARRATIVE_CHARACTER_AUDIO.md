# 15. キャラクター・物語・会話・音声演出（v0.4）

ユーザー提供のキャラクター参照画像と docs/11_UI_MOCKUPS_V03.md を基準にした**新規補完案**。ゲームに登場する人物や台詞は創作であり、実在の人物・店とは無関係。名前は仮称であり、デザイン承認時に変更可能。

## 1. 主役の役割（重要）
- ユーザーが指定した銀〜薄紫色の短い髪、左右のお団子、ピンク色の瞳、ピンク色の丸いヘアピンが**ゲームの顔となる主人公（店主）**。
- 呼称は仮に「店主」（ゲーム中の表示名は後で決定）。タイトル、MORNING、OPEN、COOK、RESULTに登場し、プレイヤーを案内する。
- **元画像の青色デニムオーバーオール/白Tシャツの衣装は再利用しない。** 店舗服はクリーム色のシャツ、ワインレッドの前掛け、柔らかいリボン等の別デザイン（細部はデザインシート承認で確定）。
- 料理の評価を付ける主体は**注文した顧客**。店主は喜ぶ/緊張する等の同時リアクションを取れるが、客の味覚判定を代行しない。
- テキスト/音声で「店主が見た評価」と「客の実際の台詞」を明確に区別する。

## 2. 固定登場人物（MVP）
| ID | 役割 | 見た目・性格の方向 | 好み（甘/コク/酸） | ランク別差分 |
| --- | --- | --- | --- | --- |
| owner | 店主・案内役 | 銀髪の双お団子・ピンク瞳。明るいが調理に真剣 | 評価対象外 | 通常/励まし/嬉しい/落胆 |
| regular | 近所の常連 | 落ち着いた年上の客。親しみやすい | 50/60/40 | SSS/S/A/B/C/F |
| student | 学生 | 快活な若い客。甘め好き | 80/50/20 | 同上 |
| worker | 会社員 | 忙しいが食にこだわる | 30/90/30 | 同上 |
| tourist | 観光客 | 町の食文化を知りたい客 | 40/50/80 | 同上 |

※キャラ固有の姓名・ボイス・年齢などはまだ承認前。服装やポーズは既存IPの再現を避ける。各顧客は独立したオリジナルデザインにする。

## 3. Day1〜Day7のMVP物語
- **前提**: 商店街に開いた小さなかつめし食堂。最初は客に知られていないが、店主が調理とたれ研究を重ねて少しずつ評判を得る。
- Day1「初めての一皿」: 開店準備、固定8件の練習営業、6工程と結果をチュートリアル化。最後に「今日はありがとう。明日はもっと美味しくできるかも！」を表示。
- Day2「揚げ方の工夫」: Day1の閉店後に購入したフライヤーがDay2から有効。設備によりP3判定の幅が変化することを案内。
- Day3「ゆったりした席」: Day2閉店後に椅子が購入可能になり、Day3から効果が有効。待ち時間の仕組みを案内。
- Day4「いつもの顔」: 初めて常連台詞が入る。顧客タイプはDay1から登場済み。
- Day5「たれを研究」: 3スロットの配合を見直す会話。初日から操作可能な機能を新しく「解放」したかのように表現しない。
- Day6「口コミが広がる」: 直近の評価履歴を振り返る会話。評判値の表示だけで追加効果はなし。
- Day7「街の人気店へ」: 7日間の累計を表示するデモ用の節目画面（エンディング相当）。
- MVPの節目条件は「Day7の閉店を1回経験すること」。評判や金額によりメッセージを変えるが、達成失敗で進行不能にしない。Day8以降も通常営業を繰り返せる（エンドレス）。
- v1以降のかつめしの日イベントは **ゲーム内5/29** に実施。想定開始日を5/22にするとDay8が5/29となるが、MVPではカレンダー演出自体を表示しない。

## 4. 物語/会話発火
- ストーリーは `storyEventId` 単位で `seenStoryEventIds` を保存し、同じ会話を複数回発火させない。
- 昼の注文生成や調理時間を止めないよう、基本の物語会話はMORNINGまたはRESULTで表示（時計停止）。注文中の長尺イベントは禁止。
- 会話データ: `id, speakerId, textKey, portraitAssetId, trigger, priority, once, nextId`。表示優先度 `tutorial > mandatory_story > optional_comment`。
- 会話完了/スキップは既読扱いとする。ストーリーに経済パラメータの増減は紐付けない（MVP）。 
- 再現性のため、同じ日に複数イベント条件を満たす場合は `priority, id` 順に安定ソート。

## 5. 台詞テンプレート
| 場面 | 誰 | 例 |
| --- | --- | --- |
| 開店 | 店主 | 「今日もおいしい一皿、届けよう！」 |
| 甘さ好み | 学生 | 「ちょっと甘めのたれだとうれしいな。」 |
| コク好み | 会社員 | 「コクのある味だと午後も頑張れそう。」 |
| SSS | 常連 | 「これはいいね！ また食べに来るよ。」 |
| S | 観光客 | 「加古川の味っておいしいね！」 |
| C | 学生 | 「次はもう少し甘いほうが好きかも。」 |
| F | 会社員 | 「今日はちょっと残念。またお願いするよ。」 |
| Day1結果 | 店主 | 「最初の一日が終わったね。次はたれを工夫してみよう！」 |

- 暴言・容姿批判などは避け、低ランクも再挑戦したくなる自然な反応にする。
- 顧客4種類×評価6ランクのセリフはMVPで最低24件、注文ヒントは各2件以上を用意。外部文字列JSONで管理する。
- 店主の表情は評価ランクとは別に、喜/平常/困/応援など4種を最低限用意。1人を6人分の顧客アセットの代わりにしない。

## 6. リアクション演出
- SSS: 大きな一皿＋顧客の最大の喜び＋店主の喜び、ゴールドの評価ロゴ、粒子、ジングル（画面揺れは削減可能）。
- S: 顧客の嬉しそうな表情＋少し強いキラキラ。A: 明るい笑顔。B: 穏やか。C: 控えめな戸惑い。F: 落胆と建設的な台詞。
- 評価UIは `score, rank, customerId, ownerReaction, foodAssetId, dialogueKey` から生成。S以上のランクでも顧客表情が欠落した場合は同キャラの通常顔＋文字表示へフォールバックする。
- 動画にしない軽量アニメで実装する（静止画差分＋スケール/透明度/粒子）。

## 7. BGM/SE（MVP）
| ID | 発火 | 優先と仕様 |
| --- | --- | --- |
| bgm_title | タイトル表示中 | ループ、低音量 |
| bgm_shop | MORNING/OPEN | ループ、営業画面間は可能なら継続 |
| bgm_cooking | COOK | 揚げ音に負けない控えめなループ |
| bgm_result | RESULT/UPGRADE | 短い結果曲または静かなループ |
| se_click | ボタン確定 | 同時連打しても音が重なり過ぎない |
| se_purchase | 仕入/設備購入成功 | 1回のみ。拒否では再生しない |
| se_fry | P3揚げ中 | ループ、PAUSE/切替で停止 |
| se_serve | SERVE成功 | 1回のみ、二重精算を示さない |
| se_rank_sss | SSS演出 | 短いファンファーレ、最大3秒 |
| se_rank_other | S/A/B/C/F | ランクに応じて強弱を付ける |
| se_error | 無効操作 | 音量を抑える、文字で理由を表示 |

- BGMとSEは別音量0〜100%。ブラウザ音声再生は初回クリック後に解放。
- 2026-11-22: オリジナル合成のBGM4曲とSE11種をWAVで作成し、`public/assets/game/audio/manifest.json` に記録。設計は `assets/source/audio/v03/design.json`、生成コードは `scripts/generate_audio_assets.py`。全音源は `concept_review` で、実機での聴取・ミックス確認が必要。
- ボイスは**MVPに入れない**。リップシンク/音声合成はv1以降。
- 音がなくても進行できる。音・光・演出のデータにゲーム内会計トリガを置かない。

## Day7実績の集計元（v0.5）
Day7の節目は `phase=RESULT` で一度表示し、過去分の `careerLedger` とDay7の `dailyLedger` を加算して累計売上/提供皿数/評価傾向を表示する。Day8以降は過去の注文明細を使わず要約値だけを使う。会話IDは `seenStoryEventIds` で二重発火防止。
