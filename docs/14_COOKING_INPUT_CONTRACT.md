# 14. 調理6工程の入力と採点（実装規範 v0.4）

既存の docs/02_COOKING.md の配点・ランク体系を変更せず、入力や再試行に不足する詳細を固定する。工程の操作秒数は現実の調理の安全基準ではなくゲーム演出用。実装後の難易度調整に備え定数をデータで管理する。

## 共通UI・データ
- 一度に1注文・1料理。現在工程番号 `stageIndex=0..5`、現在の入力 `stageInput`、工程の得点 `completedScores`、残り再試行回数をCookingSessionへ保存する。
- 各得点は有限の実数。各工程に `0<=score<=maxScore`。途中は丸めず、合計後に `Math.round` する。
- `pointerDown`は工程開始、`pointerMove`は描画のみ、`pointerUp`は確定。ただしタイマー系はボタン押下で確定。クリック操作の再入力で既存点を二重加点しない。
- UI座標と描画拡縮は正規化値0..1で扱う。1280×720と1920×1080で同じ正規化操作なら同じ採点。
- リトライは現在工程だけの入力・得点を初期化し、通常営業では **1皿あたり1回**。チュートリアルは無制限。営業時計と他のqueued客の時間はリトライ中も進む。

## P1 肉の下処理（最大15点）
- 肉上の打点ガイド3個を左→中央→右の順に表示。ターゲットの正規化水平位置 `[0.25,0.50,0.75]`。
- ガイドごとにクリックした実際の水平位置 `x[i]` を記録。各打点誤差 `e[i]=clamp(abs(x[i]-target[i])/0.25,0,1)`。
- `thicknessError01=mean(e[0..2])`、`score=15*(1-thicknessError01)`。
- 3打点全て入力すると工程完了。打点ガイド外は無効でなく誤差上限1としてカウント（すぐ改善点を伝える）。
- 肉が平たくなるアニメは入力後の演出。画面更新の遅延は採点に影響しない。

## P2 衣付け（最大15点）
- 表面を3区画に分け、左から順にドラッグまたはクリックで被覆率 `coverage[3]` を保存。各区画の被覆率0..1。
- ドラッグ: 対象区画で指/マウスが有効領域内を通過した線分の重複しないセル数/全セル数で被覆率を求める。実装は各区画10セル（合計30セル）を採用。セル境界は固定。
- 代替クリック: 指定区画をクリックする度に未被覆セルを1つ塗る。10クリックで満点。クリック順は左→中央→右でなくてもよい。
- `score=15*mean(coverage)`。1区画でも操作済みなら「次へ」有効にする（塗り残しは減点）。0操作での次へ不可。

## P3 揚げ（最大30点）
- タイマー開始ボタンで `stageElapsedSeconds=0` から計測。目標引き上げは10秒。
- 「引き上げ」押下で `t=abs(stageElapsedSeconds-10)` を記録。設備なし: `score=30*max(0,1-t/5)`、新フライヤー所持: 分母6。
- 表示の油温（例175℃）は**MVPでは装飾情報**。採点にも隠れ状態にも影響しない。実際に油温を操作させるUIは設けない。
- 0〜20秒で強制終了しない。プレイヤーが放置しても押下でき、点数は0に収束する。PAUSE/visibility hidden中はタイマー停止。
- P3得点が0でも提供を許可。失敗説明は「揚げ時間が目標から離れた」と表示。

## P4 たれプリセット選択（固定20点＋嗜好補正）
- MORNINGで保存したプリセット（最大3、空枠選択不可）から選ぶ。COOK中は編集不可。
- 初期レシピ1件 `basic=(50,60,40)` は常に有効。選択操作しないまま「次へ」でもbasicを使う。
- 得点20点は固定。**P4の操作内容は技能得点を変えない**。客の好みとの適合は最後に `b=15-0.3*d` で計算。
- 選択時点の `sauceSnapshot` を保持。翌朝以降にプリセットを編集しても進行中/提供済み注文の好み補正が変わらない。

## P5 キャベツの茹で具合（最大10点）
- 「茹で始める」押下からタイマーを進め、目標4秒。
- 「取り出す」押下の差 `t=abs(stageElapsedSeconds-4)` で `score=10*max(0,1-t/4)`。
- P3と同じ停止/再開/保存規則を使用。未開始なら「取り出す」は無効。

## P6 盛り付け（最大10点）
- 4つのパーツを順に表示し、スロットへ配置: `rice`, `cutlet`, `sauce`, `cabbage`。
- 各パーツに正しい配置スロットを一つ持たせる。正しい位置に配置できた場合に2.5点、間違ったスロットでも操作として確定するが0点。ドラッグとクリック（選択→スロット選択）の両方を許可。
- 順序はUI上では米→カツ→たれ→キャベツを案内するが、誤順序で置いた時はそのパーツ0点として扱う。次のパーツへ進むので進行不能にしない。
- 4パーツすべてを一度ずつ配置すると提供ボタンが有効。二重配置は不可。合計0〜10点。

## 最終採点
`q = P1+P2+P3+20(P4)+P5+P6` で理論範囲20〜100。
`d=(|S1-C1|+|S2-C2|+|S3-C3|)/3`、`b=15-0.3*d`。
`score=clamp(Math.round(q+b),0,100)`。閾値: 95以上SSS、85以上S、70以上A、55以上B、40以上C、それ未満F。

- 顧客嗜好は0〜100の有限数。P1〜P6の状態が壊れているならSERVEを拒否して復旧エラーとする。
- 調理結果は `qualityBreakdown` と `score` と `rank` を保存。REACTIONは保存した結果だけを参照。
- たれ選択を変更しても同じ入力なら基礎品質qは不変。顧客が違ってもqは不変。
- 参照点: q=80,d=0→95/SSS、q=80,d=50→80/A、q=20,d=100→5/F、q=84.5,d=50→85/S。

## 明確に後回しにするもの
油温操作、肉の実際の厚さ物理計算、調理機器の故障、カツの種類による揚げ時間差、工程のショートカット/自動調理はv1以降。MVP画面にダミーの操作部を置かない。

## v0.5 入力の補助と競合
- P2のクリック代替は30クリックで満点となりうるが、キーボードでは区画選択後にEnter/Spaceを0.6秒押し続けてその区画を一括塗りできる。キーリピートは無視、keydown〜keyupの実測時間で一回だけ確定。
- pointercancelやページ非表示で途中のストロークは破棄し、確定済みセルのみ保存。P3/P5のタイマーは再開の明示操作後まで止める。
- たれbasicは不変の初期プリセット。完成点数の再計算はSERVE時に一度だけ実施、REACTIONは保存値を表示する。
