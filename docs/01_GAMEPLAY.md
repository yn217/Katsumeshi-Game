# 01. ゲームループと進行仕様

## コアループ
朝の準備 → 仕入れ/たれ配合確認 → 開店 → 注文受付 → 調理 → 提供時に会計/評判確定 → 試食リアクション（時計停止） → 閉店集計 → 設備投資 → 翌日

1日の意思決定「今日は何を仕込むか」が営業中の展開を変え、料理の成績が翌日の資金・評判・来客に効く。

## 主要状態と遷移
| 状態 | 操作 | 完了条件 |
| --- | --- | --- |
| TITLE | はじめから/つづきから/設定 | 新規または既存データ選択 |
| MORNING | 仕入れ・たれ試作・準備（MVP価格は固定） | 開店ボタン |
| OPEN | 来客・注文キュー・選択 | 注文を選びCOOKへ |
| COOK | 下処理→衣→揚げ→たれ→キャベツ→盛り付け | 提供確定でREACTIONへ |
| REACTION | 提供確定済みの評価・リアクション表示 | 確認/スキップ後OPENへ |
| RESULT | 売上、原価、固定費、満足度、評判、ロス | UPGRADEへ |
| UPGRADE | 設備や店舗装飾を購入 | 翌日MORNINGへ |
| PAUSE（オーバーレイ） | 再開/設定/セーブして終了 | 元phaseへ |
| EVENT（v1オーバーレイ） | イベントの説明と選択 | 元phaseへ |

状態遷移のガード: COOK中の二重提供禁止、会計二重計上禁止、閉店後の注文生成停止。ポーズ中はゲーム内時間を進めない。

## 時間仕様（初期値）
- 通常日の営業時間: 実時間10分、調整可能な定数。
- チュートリアル初日: 注文8件を固定順で出し、時間制限と待機切れを無効化（全件終端で閉店）。
- 通常日: 来客10〜14件/日を目安に確率調整。待機列最大3人。
- 通常客の基本待ち時間: **180秒**。queued中のみ忍耐を減らす。他のqueued客の忍耐はCOOK中も減る。受付済みcooking客は期限切れなし。REACTION/PAUSE中は時計停止。
- queued中の待ち時間0で客が退出、売上0、評判が小さく低下。失敗が連続しても即ゲームオーバーにはしない。
- 初期は1注文=1皿。多皿/団体注文は後続。

## 1日の体験例
- 仕入れ: 在庫と今日の予測を見てビーフ肉や米を購入。
- 注文: 「コクのあるたれが好き」など短いヒントと忍耐ゲージを表示。
- 調理: 6つの短い操作で一皿を完成。ミスは品質スコアに反映。
- 提供: 完成料理を拡大し、キャラクターの表情＋セリフで結果を提示。
- 閉店: 売上と経費、リピート、評判変化、明日のイベントを確認。

## 進行と解放
| 区分 | 解放目安（暫定） | 内容 |
| --- | --- | --- |
| 序盤 | Day 1 | 基本ビーフかつめし、たれ調整 |
| 初週 | Day 2〜7 | 4タイプの常連会話、フライヤー改善、店内装飾 |
| 中盤 | Day 8〜14 | ポーク、チキン、新規たれ枠 |
| 発展 | Day 15〜21 | エビ、スタッフ、街の催し |
| 節目 | ストーリー上の5/29 | かつめしの日イベント |
| エンドレス | 以降 | 評判・収集・限定注文 |

日付はゲーム内カレンダー。現実の日付に依存せず、イベント日を到達できるよう設計する。

## チュートリアルシナリオ（必須）
T01 タイトル開始 → T02 仕込み画面の見方 → T03 最初の注文 → T04 肉を平たくする → T05 衣付け → T06 揚げる → T07 たれ調整 → T08 茹でキャベツ → T09 盛り付け → T10 料理評価/お客の反応 → T11 営業結果 → T12 翌日へ。

- 1回に1つの操作のみハイライト。操作可能領域以外は暗転。
- 説明後にプレイヤーが実行して進む。失敗時はその場で再試行できる。
- 再プレイ時はチュートリアルのスキップ可。

## 長期報酬
- 図鑑: 発見したたれ・料理・客の好み・店のエピソードを登録（v1以降）。
- 目標: 初常連、10食販売、初SSS、たれレシピ完成、人気店認定など。
- 実績の報酬はゲーム内装飾など、バランス崩壊しないものを優先する。

## エラー/中断
- 店を閉める/タイトルへ戻る前には自動保存し、保存結果を通知する。
- 調理途中で離脱した場合は直前の確定ステップから再開、進行不能なら注文破棄処理を用意。
- 未確認のイベントがある場合も翌日の状態復元が可能。

## 営業時計・閉店の決定仕様（v0.2）
1. 永続化するphaseは MORNING / OPEN / COOK / REACTION / RESULT / UPGRADE（TITLEはメニュー画面）。PAUSE/EVENTはphaseではなくオーバーレイ。元phaseと操作途中を保持する。
2. 通常営業の時計は600秒。**OPEN・COOKだけ**残り時間を減算し、queuedの忍耐も減らす。初日チュートリアルは600秒の制限を無効にする。
3. 受付済み注文はcookingへ入り、以後その客の忍耐は減らない。別のqueued客は減る。queued最大3件、cooking最大1件。
4. 残り時間0では**新規来店のみ停止**。queued注文は受付/期限切れまで、調理中注文は提供/キャンセルまで継続。残り時間0でもqueuedの忍耐は減る。
5. 残り時間0、queuedが0、cookingが0、REACTION表示中ではない場合にCLOSE_DAYを1回発火。初日は生成された8注文がすべて終端に達すると閉店する。
6. SERVE時に売上・評判を確定し、REACTIONでは表示のみ。REACTION中はゲーム時計を停止し、DISMISS_REACTIONでOPENへ復帰する。
7. RESULTで固定費決済済み。必ずUPGRADEを経由してNEXT_DAY→MORNINGへ進む。

## v0.5 補足：チュートリアルと設備の順序
- Day1の最初の注文は必ず提供とREACTIONを経験してから次へ進む。初回だけCANCEL_ORDERを無効化。
- Day1結果→UPGRADE（まだday=1）で **Day2から有効なフライヤーを購入できる**。椅子はDay2結果→UPGRADEで初めて購入可。設備のunlockDayは使用開始日。
- コマンド・時刻・保存の正規順序は[20](20_EVENT_STATE_PROTOCOL.md)が優先。
