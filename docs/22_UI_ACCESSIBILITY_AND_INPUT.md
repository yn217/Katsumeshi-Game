# 22. UI状態・入力・アクセシビリティ実装仕様（v0.5）

docs/04/13の補完。高解像度モックアップはコンセプト画像であり、その中の数値や表示文字は実装値ではない。

## 画面の論理領域と最小寸法
- 背景/シーンは1600×900の論理キャンバスを16:9で維持し、画像は等比拡大・縮小可。
- **テキスト・入力フォーム・ボタンはブラウザCSSレイアウトで描く**。画面全体をCSS transformで縮小して文字を小さくする方法は禁止。
- 標準文字は画面実ピクセル18px以上、補助文字は最低16px（要アクセシビリティ実機確認）。主要操作ボタンの高さは40px以上。1280×720でも読める・押せること。
- ゲームUIは上部ヘッダー/中央ゲーム/下部メッセージ。1280×720以下で縦方向不足ならサイドパネルのみ縦スクロール可能とし、画面外ボタンを不可視にしない。
- 16:9以外は背景レターボックスでもUIが画面内に収まる。画面幅が狭い場合は注文サマリーと作業画面を切替タブに変更（MVP PC優先）。
- 1920×1080固定ステージは同寸以上の横長ビューポートでだけ使う。それ以外の幅1280px以上の横長表示は流動レイアウトとし、アプリ全体transformで縮小しない。流動レイアウトでは本文18px、補助文字16pxをCSS実寸で保つ。
- 右側の注文カードは最大3、1枚の表示に顔・種類・忍耐残・料理名・好みヒント・受付ボタンを含む。全カードが重なったり消えたりしない。

## UIの5種類の状態
| 状態 | 表示/入力 |
| --- | --- |
| loading | ゲームタイトルと進捗、操作不能 |
| ready | ホバー/フォーカス/クリックの視覚フィードバック |
| disabled | 理由テキスト＋灰色表示、クリックで副作用なし |
| saving | セーブ中を表示、二重終了を抑制 |
| error | エラー理由、再試行ボタン/安全に戻る動線 |

- 画面ごとの空表示: 注文0件「来客を待っています」、素材0個「仕入れてください」、セーブ無し「はじめから」、該当する実績無し「まだありません」。
- MVPに存在しないメニューは無効ボタンで残さず、UIにも表示しない。
- ネット接続不能でもローカルMVPとして動作し、プライベートモードでセーブ不可の場合は始める前に注意を表示（ゲーム続行は可能、永続化は保証しない）。

## 色コントラスト
- 通常サイズのUI文字と背景のコントラスト比は4.5:1以上、大きな文字（18pt以上、太字14pt以上）は3:1以上を目標とする（WCAG 2.2 SC 1.4.3）。
- 背景画像や半透明パネルに重なる文字は、合成後の実画面で確認する。単色tokenの比率だけで画面全体の適合を宣言しない。
- 評判の増減など状態を伝える表示は、色に加えて符号/ラベルでも意味を示す。

## 入力ルール
- マウス: クリックで決定、ドラッグ工程でpointerdown→pointermove→pointerup。pointercancel/画面外ドラッグ/右クリックでは途中の操作を破棄、確定済みセルだけ保持。
- キーボード: Tab/Shift+Tab、Enter/Spaceで決定、Escでmodal/PAUSE、Rで工程再試行（有効な時のみ）。Escで勝手にCOOKをキャンセルしない。
- P2代替: 3区画ボタンをTabで選択し、Enter/Space **長押し0.6秒で区画の未被覆セルを全て塗る**（一度で当該区画100%）。通常クリックで1セルずつ進む方式も保持。代替の採点結果は実際に塗れたセル数で決まり、画面縮尺に依存しない。
- P6代替: Tabで次の部品を選んでEnter。選択後は配置スロットへフォーカスが移るのでEnterで確定する。誤配置も0点として確定し、進行不能にしない。4部品の配置後、提供ボタンを有効にする。
- P3/P5: タイマーのスタート/停止は大きなボタン、Space/Enterで代替。モーダル表示中のSpaceは画面奥のタイマーを誤操作しない。
- 音量/画面揺れ削減/テキスト送り速度/演出スキップ設定はタイトルから変更可。音がなくても全状態を理解できる。

## たれプリセットUI
- `basic`は初期・固定スロット（編集/削除不可）。カスタム2枠は空でスタートし、MORNINGで新規保存・上書き可能。
- 数値は甘さ/コク/酸味いずれも0〜100、10刻み。保存前にはプレビューのみ変わり、開店で未保存なら破棄確認を表示。
- P4は保存済み3枠のいずれかを選ぶ。空枠の選択はできない。何も選ばなければbasic。顧客ごとに変えても再編集はMORNINGでのみ可能。

## 画面ごとの追加表示
- MORNING: 本日の予想候補人数、現在の食数可能在庫=min(5材料の在庫)、不足材料、立て直し支援の可否、施設購入はここでは不可。
- OPEN: 残営業時間は0秒で止め、注文待機カードの忍耐は残客対応が終わるまで減る。調理中の客カードは待機から消える。
- COOK: 進行ステップP1..P6、工程の残り再試行回数、開始前と計測中のタイマー状態、現在のお客の好みヒントを常時表示。
- REACTION: 大きな完成料理、評価を付けた顧客の顔/言葉、店主は補助出演、得点・ランク。売上と評判は既に確定。
- RESULT: 営業利益と現金増減を混同させない。売上/消費原価/固定費/設備投資/現金収支をラベルを変えて表示。
- UPGRADE: **今がDay1でも翌日Day2で使えるフライヤー**は購入可。「翌営業日から有効」と説明。購入済み/残金不足を明示。

## ダイアログ/アニメ
- `aria-modal="true"` のダイアログは表示直後に内部の操作要素へフォーカスし、Tab/Shift+Tabを内部で循環させる。
- 確認モーダル（削除・新規開始・調理破棄・上書き）は2操作「決定/キャンセル」を置く。
- 口調は日本語。顧客が評価主語であることを名前ラベルで示す。SSSでも低ランクでも一皿と人が重ならず、表情が分かる。
- リアクション演出をクリック連打しても一度しか表示状態を進めず、二重のSERVE呼出なし。画面揺れは削減設定で無効。光は点滅を抑える。
- フォーカス喪失時はPAUSE表示、戻った時にプレイヤーが明示再開するまで時間を進めない。

## ローカライズ・UIテスト
- 本文・UIボタンはすべて外部の `textKey` とデータから表示。PNG内に金額/役割名/ボタン名を書き込まない。
- 1280×720、1600×900、1920×1080、16:9外（例1366×768）の自動スクリーンショットを残し、3注文表示/店主と客の表示/調理ゲージ/固定費結果の重なりを目視レビュー。
- Canvasの当たり判定を正規化座標から変換し、同じ入力（中心点をクリック）なら倍率に関係なく同じ調理スコアを得る。
