# 08. 開発ロードマップ・テスト・受け入れ基準

## ステージ定義
| フェーズ | 目的 | 成果物 | 完了条件 |
| --- | --- | --- | --- |
| P0 企画確定 | 機能境界・技術・画風を固定 | docs一式、画面遷移、データ定義 | 矛盾なし、未決項目の明記 |
| P1 画面プロトタイプ | 操作感の早期確認 | タイトル、店舗、調理、反応、結果 | 全画面遷移を手動操作できる |
| P2 調理MVP | 1皿を完成 | P1〜P6、score、評価演出 | 100回連続で調理可能 |
| P3 営業MVP | 1営業日を遊べる | 注文、待ち、在庫、会計、閉店 | 初日8件・売上/原価/現金の照合 |
| P4 成長・保存 | 続けて遊べる | 翌日、たれ研究、設備2種、セーブ | 3日分の進行を復元可能 |
| P5 アセット統合 | 一貫した見た目 | キャラ/料理/店舗、SSS〜F差分 | 画風・位置・ライセンス確認 |
| P6 品質確認 | リリース可能なデモ | バグ修正、バランス、操作試験 | ブロッカー0、受け入れ試験通過 |

## Issue分割（推奨タイトル）
1. setup: Vite/React/TypeScript/PixiJS最小構成と検証コマンド
2. docs: データスキーマとゲーム状態機械の実装
3. cooking: P1〜P6入力・評価・再試行
4. economy: 仕入/在庫予約/売上/日次会計
5. customer: 4タイプと注文キュー・待ち時間
6. sauce: 3軸調整・プリセット保存・好み補正
7. reaction: SSS/S/A/B/C/F演出と台詞
8. ui: タイトル・仕込み・営業・調理・閉店・設定
9. upgrade: フライヤー・椅子と店舗進行
10. save: バージョン付きセーブと復旧
11. assets: ComfyUI既存画像情報の棚卸し、LoRA設定と制作テンプレ
12. assets: 料理完成形、キャラクター、背景の統一生成とレビュー
13. qa: E2E操作・パフォーマンス・セーブ耐久・解像度
14. polish: 音・演出・チュートリアル

実作業時はIssueを優先順位・依存関係ごとに細分化する。最優先は 1→2→3→4→5→8→7→10。外部アセット制作は並行可能。

## 必須のユニットテスト
- 調理品質と好みの補正式（最大最小、境界点、丸め）
- 全ランクの境界（39/40,54/55,69/70,84/85,94/95）
- 所持金以上の購入を拒否、マイナス材料を拒否
- 仕入支出と消費原価の分離
- 同じ注文IDの二重提供・二重会計を防ぐ
- 残り待ち時間0の注文が退出し、売上は0
- イベント重複発火・ステート遷移違反を拒否
- セーブv1が同値に復元される
- スキーマ不正・参照不整合・読込失敗でデータ消失しない

## E2Eシナリオ
E01: 新規開始→最初の注文→6工程→提供→S評価→売上反映→閉店。
E02: 8件完走→売上・材料原価・ロス・固定費の集計。
E03: たれの配合を変え、同じ客のscoreが変化。
E04: 待機列が最大3を超えず、時間切れ客が退出する。
E05: 仕入可能/不可能、設備購入可能/不可能の表示が正確。
E06: 調理中にセーブ終了→復元→続きをプレイ。
E07: 試食演出のスキップ・高速連打で会計が二重発火しない。
E08: 1280×720で注文カード/在庫リスト/セリフに重なりがない。
E09: バックグラウンドタブ→復帰で時計が飛ばない。
E10: 無効なセーブを読み込んでも既存スロットが残る。

## アセット検証
- 全立ち絵: 人物の顔、服、手、全身、透明背景、左右、主なアクセサリーを点検。
- 全完成料理: 皿が見切れず、米・カツ・ソース・茹でキャベツが識別できる。
- たれ差分: カメラ角度・皿形状・料理配置がズレない。
- 画面合成: 1920×1080/1280×720の完成画面で視認性を確認。
- 生成ワークフローのモデル・LoRA・seed・ライセンス情報を記録する。

## パフォーマンス検証
- 初期ロード3秒以内（PC、キャッシュ後の目標）。
- 店舗/調理画面で目標60fps。計測の対象PCとブラウザを記録する。
- 10分連続プレイでメモリの継続増加を起こさない。
- 画像失敗・遅延時も注文状態・会計が壊れない。

## MVPリリースゲート
- [ ] ブラウザでタイトルから翌日まで進める
- [ ] 8件の注文が完了し、日次収支が正しい
- [ ] 6工程の成績が評価に反映される
- [ ] たれの好み補正が客ごとに機能する
- [ ] SSS/S/A/B/C/Fすべての反応が表示される
- [ ] 1日をまたぐセーブ・復帰ができる
- [ ] 1280×720で操作不能なUIがない
- [ ] ブロッカー/高深刻度バグ0
- [ ] アセットの出典・使用権を記録済み

## リスク
- アセットの画風不統一 → 代表キャラ/完成料理を先に固め、他は後から生成。
- ミニゲームが長く単調 → 工程の目標時間を計測し、短縮・スキップ可能性を検討。
- 経営が赤字ばかり/簡単すぎ → 再現可能なseedで最低/平均/最高成績の3ケースを自動試験。
- 保存破損 → スキーマ検証、原本保持、復元試験。
- 個別のローカル環境に依存 → アセット生成と本番ゲーム実装を分離。

## v0.2で必須となる境界テスト
- T11: 通常営業の残時間0で来店生成が止まり、queued3件を処理または期限切れにすると閉店する。
- T12: queued客180秒で期限切れ。ACCEPT_ORDERの瞬間からその注文の忍耐が停止し、COOKが180秒を超えてもcooking客は離脱しない。
- T13: REACTION中に時間を長く経過させても営業時間・他客の忍耐が減らない。
- T14: 8件提供したチュートリアル初日は売上7,840、消費原価3,440、固定費2,200、営業利益2,200、現金35,640、残在庫2食分。
- T15: cooking途中キャンセルは原価430・waste430・売上0。利益からwaste430を二重に引かない。
- T16: 保存→復旧→完成/スキップ→再表示で在庫・売上・評判・固定費が二重更新されない。
- T17: COOKの工程途中、特にP2ドラッグの確定操作とP3/P5の経過秒数を復元。プリセットが後日変わっても進行中の配合は不変。
- T18: 1920×1080と1280×720で料理・立ち絵・セリフが重ならず、たれ差分の皿中心ズレが2%以内。
- T19: 固定価格980円の画面に変更可能に見えるコントロールがない。
- T20: Day1は4タイプ全員登場可能、Day2からは会話/イベントの新規解放とし、客タイプの重複新規解放をしない。
- T21: 20/80/100点基礎品質の嗜好補正、最終一回丸めを比較し、境界94→S・95→SSS等が正しい。
- T22: 仕入不足時の受付拒否は在庫・原価・現金・注文状態を一切変えない。
