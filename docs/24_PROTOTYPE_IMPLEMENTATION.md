# 24. 初期操作プロトタイプ実装状況（2026-11-22）

## 実装の目的
現行設計のv0.5を、まず操作可能なブラウザ画面と独立したゲームコアとして試す。**実装形式は依存不要のJavaScript ES Modules**。企画の推奨構成（Vite/React/PixiJS）と異なるのは、初期検証とセットアップの単純さを優先するため。完成版のフレームワーク選定は未確定。

## 仕様に対して動く初期機能
- Day1: 固定順の8注文を1件ずつ発行。初回提供までキャンセル拒否。時間無制限。
- 通常日: 600秒、評判に応じて候補10〜14、固定時刻来店、queued3件まで・cooking1件。満員逸失と期限切れ。
- 料理: P1肉の3点クリック、P2衣の3区画塗り、P3揚げタイマー、P4たれプリセット、P5茹でタイマー、P6盛り付け4部品。
- 評価: 工程得点＋たれ嗜好補正、SSS/S/A/B/C/F、売上/評判を提供時に確定。
- 経営: 5食材仕入れ、補填型の無料支援、フライヤー/椅子、Day1→Day2以降、日次/累計帳簿。
- 保存: IndexedDB main/backup（同じtransactionで更新）、手動保存して終了、重要操作後の自動保存、調理中の定期保存、復元時PAUSE。

## 仕様との差分・既知の制限
- キャラクターは絵文字による仮表示。ユーザー指定の銀髪・ピンク瞳の店主の正式な透明PNGは未分割。衣装は参照画像のデニム服を使用しない。
- 料理・背景も仮のCSS/絵文字表現。GitHub登録済みの画面モックをボタン付き一枚絵として転用していない。
- P2のクリック代替として「まとめ塗り」ボタンを用意。v0.5の長押し0.6秒操作は未実装。P2の厳密なドラッグセル被覆も未実装。
- P1は画面内クリックのx比率で採点。P6は部品を所定順に表示し置き場を選択する簡易版。
- タイマー/DOMは100ms単位で表示を更新。性能計測と描画負荷の最適化は未実施。
- 日本語は画面上に直接仮文言として記述。外部textKeyによる完全なローカライズは未対応。
- Web Audio/BGM/SE・チュートリアルの段階的フォーカス・人物別24表情差分は未対応。
- IndexedDBは構造を最低限確認してロードする。ランタイムの完全なJSON Schema / cross-field validationは未実装。
- 旧mainをbackupへ保存する仕組みはあるが、初回保存時にバックアップが無いことがある。
- ゲーム内の調理秒数は短縮した演出であり、実際の食品調理の安全基準ではない。
- Windows/モバイル/実機での操作結果や60fpsの到達は未確認。
